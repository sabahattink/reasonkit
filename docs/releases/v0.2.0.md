# ReasonKit v0.2.0

ReasonKit v0.2.0 is a frozen, candidate-backed release of the compact
instruction and orchestration surface. It focuses on selective context,
bounded delegation, explicit verification, and observable provenance rather
than on adding more agents.

## What is included

The v0.2 surface binds the Tiny Kernel, provider-neutral generic adapter,
module registry, `reasonkit-v02` implementation, route context plan, and
`full_bundle_fallback=false`. A host can classify a task, load the relevant
module set, authorize bounded specialists only when needed, and emit
verification and stop telemetry. The zero-agent path remains a first-class
outcome.

The v0.1 bundles and policies remain available as historical or compatibility
surfaces. They are not silently rewritten into the v0.2 candidate.

### Observed v0.2 routing

For C, the adaptive path activated with the `debugging` route at L2. It loaded
the selected `protocol.debugging` module, measured 200 module tokens, omitted
seven unrelated modules, and kept `full_bundle_loaded=false`. No specialist
was authorized or started, and no adversarial pass was requested. This is an
observed selective-routing result, not evidence that every task should avoid
specialists.

The post-run context comparison was:

`C_context_ratio = 155,471 / 169,228 = 0.9187073061`

This is within the frozen `C <= 1.25 x B` criterion. It did not influence
runtime behavior.

## Interpretation

- All four arms reached the same frozen task outcome and the same rubric
  score. This benchmark does not demonstrate a measurable ReasonKit quality
  advantage over the vanilla or Reliable Engineering arms.
- C did demonstrate the intended adaptive, observable path on this task and
  used less measured input than B in this run.
- D, Astra vanilla, used the least measured input and output overall.
- No final arm used a broad rewrite, disabled caching, edited tests or
  fixtures, added dependencies, or used evaluator-only material as input.

## Limitations

This is one held-out task and one successful final run per arm, with one
provider recovery for A. It is not statistically significant and should not
be generalized to all coding tasks or providers. Cache/read metrics and other
provider fields remain unavailable when the provider did not report them.

The package is an instruction, protocol, adapter, and evaluation surface. It
does not include provider runtime clients or claim a production deployment.
