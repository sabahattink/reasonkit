# Seven-day launch sequence

This is a staged sequence, not a one-day blast. Every external post and message remains manual and approval-gated.

## Day 1 — release surface

- Confirm the public v0.2 release link, branch/default-branch behavior, quickstart, and feedback path.
- Publish the GitHub release link from the maintained account only after the public surface is ready.
- Post the LinkedIn and X drafts with the one-task feedback ask.
- Record the starting scorecard state; do not infer users from views or stars.

## Day 2 — technical explanation

- Publish the DEV.to article only if it contains the technical explanation in the article itself, not just a repository link.
- Invite readers to try one real task and report setup friction.
- Capture direct feedback without collecting private repository contents.

## Day 3 — hands-on community test

- Recheck the current Show HN restriction and only submit if the project is genuinely easy to try.
- If still manual or confusing, keep Show HN in draft and spend the day improving the first-use path instead.

## Day 4 — one relevant community

- Choose one Reddit or public developer community whose current rules permit the post.
- Ask moderators first when the rule is ambiguous.
- Publish one substantive, community-specific post; do not cross-post the same text or solicit votes.

## Day 5 — targeted outreach

- Contact 5–10 manually selected developers from the permitted segments.
- Personalize the reason for contact and make the ask one real task.
- Do not bulk-send, scrape private data, or imply endorsement.

## Day 6 — evidence from use

- Publish one concrete usage example or an anonymized first-friction finding only if it was actually observed.
- Label it as reported, observed, or unverified.
- Do not turn a single report into a benchmark or token-saving claim.

## Day 7 — review

- Count real tries, completed first uses, repeat uses, feedback items, task categories, and setup failures.
- Write the top three friction patterns in the scorecard.
- Make only an adoption fix if the evidence supports it; do not open v0.3 architecture work.
