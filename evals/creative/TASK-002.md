# TASK-002 — Redesign a multidisciplinary technical portfolio

## Participant prompt

Use the frozen starter repository in the workspace directory to create a
public-facing portfolio homepage for a multidisciplinary technical builder
working across physical automation and software. The page should make
the work feel precise, credible, and unmistakably authored without inventing
clients, measurements, credentials, logos, or project outcomes.

Use one coherent visual or interaction system rather than a collage of
effects. The first viewport must communicate what the person makes, who it is
for, and where the visitor can go next. Include at least one meaningful
interactive state whose behavior expresses the central idea.

## Required evidence

Keep the pinned Next.js dependencies, supplied content, fonts, assets, browser,
network restrictions, and viewport contract unchanged. Provide a rendered
desktop view at 1440 by 900 and a narrow view at 390 by 844. Inspect both
renders, one keyboard or alternate-input path, reduced motion behavior, and
one representative journey from entry to contact or project detail. Label any
demo telemetry as SIMULATION.

## Creative constraints

- The first creative thesis is disposable.
- For L2 or higher creative work, generate at most three genuinely different
  theses. Variants of one layout do not count.
- Reject a direction that could belong to 1,000 other developers without
  meaningful changes.
- Use specific content placeholders where facts are not supplied.
- Prefer purposeful motion and hierarchy over decoration.

## Scoring

Score each dimension from 1 to 5, where 5 is the stronger result:

| Dimension | Meaning |
| --- | --- |
| Genericness score | 1 is interchangeable; 5 is unmistakably specific |
| Visual hierarchy | Purpose and next action are clear |
| Identity specificity | The point of view survives without the source file |
| Responsive quality | Narrow and desktop states remain coherent |
| Interaction purpose | Motion or state change has a meaningful role |
| Human preference | Blinded evaluator preference or pairwise result |

Also record generated tokens, agent count, tool calls, render_inspected, and
the final verification status. No score is considered valid without render
evidence.
