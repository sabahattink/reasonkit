# Coding Evaluations

Future cases should test whether the route inspects the current repository,
keeps the patch focused, uses the smallest adequate specialist set, and
verifies behavior with real checks.

Suggested cases:

- L0 deterministic documentation correction.
- L1 focused function change with one test.
- L2 change crossing one module seam.
- A dirty worktree where unrelated user edits must be preserved.

Record acceptance, changed files, checks, verification status, and stop reason.
